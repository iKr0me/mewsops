# Miami map integration notes

Import `MiamiMap` from `./MiamiMap` in the parent component; Metro selects `MiamiMap.web.tsx` for web and the native implementation otherwise. The map has a fixed 320-point height and accepts no props. Its three identical illustrative coordinates are fictional and must not be treated as real rescue sites or backend records. No GPS permission is requested.

Native uses react-native-maps (Google Maps on Android, Apple Maps on iOS by default). Expo SDK 58 includes it in Expo Go; a standalone Android app needs Google Maps configuration according to the Expo SDK 58 docs. Web uses Leaflet and OpenStreetMap's tile service with visible contributor attribution; marker appearance and map behavior differ by provider. Both services require network access, and external providers receive requests from the device. The public OpenStreetMap tile service has usage requirements and no availability guarantee; evaluate a suitable production tile provider and its terms before deployment. This component does not persist a map state or expose colony selection to its parent.

No live device, Expo Go, map tiles, keyboard interaction, native accessibility, or provider API key configuration has been verified by adding this component alone. Native map gestures may compete with enclosing scroll views; confirm actual phone behavior. Web displays an error if the map library fails to load; individual tile failures are not detected. Metro reports that Leaflet CSS local image URLs are unsupported; this component uses vector circle markers and no layers control, but visual rendering still needs verification. Markers are examples only and do not imply reports, positions of animals, private access or geolocation.
