# Miami map integration notes

`import MiamiMap from './MiamiMap'` resolves native or web automatically. `MiamiMapPoint` and `MiamiMapProps` are exported from `MiamiMap.data.ts` and each platform component. Props: `points?: readonly MiamiMapPoint[]` (`id`, `title`, `latitude`, `longitude`), `selectedId?: string | null`, `onSelect?: (id: string) => void`. If `selectedId` is undefined the component holds selection locally; if specified, the parent owns selection and must update the prop after `onSelect`. Both marker presses and the always-available colony list invoke the callback. An empty array shows an empty message. No navigation is implied, and map state is not shared until a parent provides shared state.

The default points use the existing seed IDs and names: colony-1 Mangrove Lantern, colony-2 Coral Courtyard, colony-3 Banyan Cove. Their coordinates are invented examples on real Miami streets, NOT actual colony locations. Current Today cards have different names, so they are not linked. The screen-owner has been asked to use the shared IDs; no automatic matching by name occurs. Callers supplying points must use authorized and appropriate location data; no permission or role enforcement is implemented here.

Native uses react-native-maps (Google Maps on Android, Apple Maps on iOS by default). Expo SDK 58 includes it in Expo Go; standalone Android apps need Google Maps configuration. Web uses Leaflet and OpenStreetMap tiles with attribution. Both require network and providers receive tile requests; evaluate OSM's usage requirements and a production tile service. No GPS permission is requested. Web displays an unavailable message on library/tile failure, retains the selectable list, and clears the message after tile loading succeeds. Native always retains the list if the map is blank; provider failures cannot currently be diagnosed by this component.

On 8 November, the existing localhost:8085 Chrome preview displayed Miami tiles and OSM attribution; clicking Coral Courtyard in the new list changed the selected state. This is a browser observation only: custom point updates, controlled callbacks, marker presses, keyboard behavior, native touch, native Expo Go, provider failures, and screen readers still require testing. Native map gestures can compete with enclosing scroll views. Metro warns Leaflet CSS local image URLs are unsupported; custom vector circles avoid default marker assets, but other CSS image-based controls should not be assumed to work. Map styles and behavior differ by provider.
